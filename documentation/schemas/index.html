    Schema and transformers¶

    Since version 1.7.0 of Datafaker it's possible to specify transformation schema.

    It also provides a set of ready to use transformers:

    • CSV
    • JSON
    • SQL
    • YAML
    • XML
    • Java Object
    • TOML

    Schema¶

    Schema is a set of rules describing what should be done to transform data from Datafaker representation to one of the supported formats. One of the main advantages of Schema is that the same schema could be used to transform to different formats.

    Schema can be used in 2 ways: it could be used to generate data from scratch or it could be used to transform existing data.

    Example of schema definition:

    Schema<String, String> schema =
    Schema.of(
        field("first_name", () -> faker.name().firstName()),
        field("last_name", () -> faker.name().lastName()),
        field("address", () -> faker.address().streetAddress()));

    val faker = BaseFaker()

val schema = Schema.of(
    field("first_name",
        Supplier { faker.name().firstName() }),
    field("last_name",
        Supplier { faker.name().lastName() }),
    field<String, String>("address",
        Supplier { faker.address().streetAddress() })
)

    def faker = new BaseFaker()

// Write closures without arguments as { -> ... }, so Groovy picks the Supplier version of field()
Schema<String, String> schema = Schema.of(
    field("first_name", { -> faker.name().firstName() }),
    field("last_name", { -> faker.name().lastName() }),
    field("address", { -> faker.address().streetAddress() }))

    It is also supported nested(composite) fields e.g.:

    Schema.of(
    compositeField("key", new Field[]{field("key", () -> "value")}));

    Schema.of(compositeField("key", arrayOf(field("key", Supplier { "value" }))))

    Schema.of(compositeField("key", [field("key", { -> "value" })] as Field[]))

    CSV transformation¶

    CSV transformer could be build with help of CsvTransformer.CsvTransformerBuilder e.g.

    CsvTransformer<String> transformer =
    CsvTransformer.<String>builder().header(true).separator(separator).build();

    val transformer = CsvTransformer.builder<String>().header(true).separator(separator).build()

    def transformer = CsvTransformer.builder().header(true).separator(separator).build()

    The following can be configured:

    • the separator and quotes could be specified with separator() and quote()
    • with or without header also could be specified with header()

    To generate data based on a schema just call generate against schema:

     String csv = transformer.generate(schema, limit);

    val csv = transformer.generate(schema, limit)

    def csv = transformer.generate(schema, limit)

    Also it's possible to use schemas to transform existing data. E.g. there is a collection of Name objects and we are going to build csv of first and last names based on this collection:

     Schema<Name, String> schema =
    Schema.of(field("firstName", Name::firstName), field("lastname", Name::lastName));

CsvTransformer<Name> transformer =
    CsvTransformer.<Name>builder().header(false).separator(" : ").build();
String csv =
    transformer.generate(
        faker.<Name>collection().suppliers(faker::name).maxLen(limit).build(),
        schema);

    val faker = BaseFaker()

val schema = Schema.of(field("firstName", Name::firstName), field("lastname", Name::lastName))

val transformer = CsvTransformer.builder<Name>().header(false).separator(" : ").build()
val csv = transformer.generate(
    faker.collection<Name>().suppliers(Supplier { faker.name() }).maxLen(limit).build(), schema
)

    def faker = new BaseFaker()

Schema<Name, String> schema =
    Schema.of(field("firstName", { Name name -> name.firstName() }), field("lastname", { Name name -> name.lastName() }))

def transformer = CsvTransformer.builder().header(false).separator(" : ").build()
def csv = transformer.generate(
    faker.collection().suppliers({ faker.name() }).maxLen(limit).build(),
    schema)

    JSON transformation¶

    JSON transformation is very similar to CSV. The main difference is that JSON supports nested values which could be handled with help of compositeField.

    Example of JSON generation:

    Schema<Object, ?> schema = Schema.of(
    field("Text", () -> faker.name().firstName()),
    field("Bool", () -> faker.bool().bool())
);

JsonTransformer<Object> transformer = JsonTransformer.builder().build();
String json = transformer.generate(schema, 2);

    val faker = BaseFaker()

val schema: Schema<String, *> = Schema.of(
    field("Text", Supplier { faker.name().firstName() }),
    field("Bool", Supplier { faker.bool().bool() })
)

val transformer = JsonTransformer.builder<String>().build()
val json = transformer.generate(schema, 2)

    def faker = new BaseFaker()

def schema = Schema.of(
    field("Text", { -> faker.name().firstName() }),
    field("Bool", { -> faker.bool().bool() })
)

def transformer = JsonTransformer.builder().build()
def json = transformer.generate(schema, 2)

    To use composite fields it should be defined on Schema level and nothing more.

    SQL transformation¶

    Note: right now only INSERT is supported.

    It generates a number of INSERT statements. There are 2 modes: batch and non batch generation.

    Batch generation means that one INSERT statement contains several rows to insert. Since different databases could have different syntax there is initial support for different dialects. Dialect could be specified during SQLTransformer build e.g:

    SqlTransformer<String> transformer =
    new SqlTransformer.SqlTransformerBuilder<String>()
        .schemaName(tableSchemaName).dialect(SqlDialect.ORACLE).build();

    val transformer = SqlTransformer.SqlTransformerBuilder<String>()
    .schemaName(tableSchemaName).dialect(SqlDialect.ORACLE).build()

    def transformer = new SqlTransformer.SqlTransformerBuilder()
    .schemaName(tableSchemaName).dialect(SqlDialect.ORACLE).build()

    Dialect also handles SQL quote identifiers, quotes and other SQL dialect specifics.

    In Datafaker 3.0, pass raw names to schemaName(), tableName(), and schema fields. The dialect quotes identifiers and escapes embedded closing quotes. For example, a PostgreSQL field named order"code becomes "order""code". Oracle rejects identifiers containing a double quote.

    An example of batch mode:

    Faker faker = new Faker();
Schema<String, String> schema =
    Schema.of(field("firstName", () -> faker.name().firstName()),
        field("lastName", () -> faker.name().lastName()));
SqlTransformer<String> transformer =
    new SqlTransformer.SqlTransformerBuilder<String>()
        .batch(5)
        .tableName("MY_TABLE")
        .dialect(SqlDialect.POSTGRES)
        .build();
String output = transformer.generate(schema, 10);

        val faker = Faker()
    val schema: Schema<String, String> = Schema.of(
        field("firstName", Supplier { faker.name().firstName() }),
        field("lastName", Supplier { faker.name().lastName() })
    )
    val transformer = SqlTransformer.SqlTransformerBuilder<String>()
        .batch(5)
        .tableName("MY_TABLE")
        .dialect(SqlDialect.POSTGRES)
        .build()
    val output = transformer.generate(schema, 10)

    def faker = new Faker()
def schema = Schema.of(
    field("firstName", { -> faker.name().firstName() }),
    field("lastName", { -> faker.name().lastName() }))
def transformer = new SqlTransformer.SqlTransformerBuilder()
    .batch(5)
    .tableName("MY_TABLE")
    .dialect(SqlDialect.POSTGRES)
    .build()
def output = transformer.generate(schema, 10)

    will generate 2 INSERT each containing 5 rows e.g.

    INSERT INTO MY_TABLE ("firstName", "lastName")
VALUES ('Billy', 'Wintheiser'),
       ('Fernando', 'Sanford'),
       ('Jamey', 'Torp'),
       ('Nicolette', 'Wiza'),
       ('Sherman', 'Miller');
INSERT INTO MY_TABLE ("firstName", "lastName")
VALUES ('Marcell', 'Walsh'),
       ('Kareen', 'Bode'),
       ('Jules', 'Homenick'),
       ('Lashay', 'Gaylord'),
       ('Tyler', 'Miller');

    Advanced SQL types¶

    It also supports generation of ARRAY, MULTISET and ROW types. Please be aware that not every database engine supports it and Datafaker couldn't do it for every dialect.

    To generate ARRAY schema field supply an array.
    To generate MULTISET schema field supply a list (SQL MULTISET could contain duplicates).
    To generate ROW schema field should supply a compositeField.

    e.g.

    Schema.of(field("ints", () -> new int[]{1, 2, 3}));

    val schema: Schema<String, IntArray> = Schema.of(field("ints", Supplier { intArrayOf(1, 2, 3) }))

    Schema.of(field("ints", { -> [1, 2, 3] as int[] }))

    will lead to

    INSERT INTO "MyTable" ("ints") VALUES (ARRAY[1, 2, 3]);

    Schema.of(field("names_multiset", () -> Set.of("hello")));

    val schema: Schema<String, Set<String>> = Schema.of(field("names_multiset", Supplier { setOf("hello") }))

    Schema.of(field("names_multiset", { -> Set.of("hello") }))

    will lead to

    INSERT INTO "MyTable" ("names_multiset") VALUES (MULTISET['hello']);

    Schema.of(compositeField("row", new Field[]{field("name", () -> "2")}));

    Schema.of(compositeField("row", arrayOf(field("name", Supplier { "2" }))))

    Schema.of(compositeField("row", [field("name", { -> "2" })] as Field[]))

    will lead to

    INSERT INTO "MyTable" ("row") VALUES (ROW('2'));

    Spark SQL¶

    Some engines like Spark stand out with support for complex types like STRUCT and MAP.
    Spark dialect doesn't support batch inserts. The dialect will throw an exception if you attempt to generate batch inserts.

    The following schema:

    Schema.of(
    field("string", () -> "string"),
    field("array", () -> new int[]{1, 2, 3}),
    field("map", () -> Map.of("key", "value")),
    compositeField("struct", new Field[]{field("name", () -> "2")})
);

    Schema.of(
    field("string", Supplier { "string" }),
    field("array", Supplier { intArrayOf(1, 2, 3) }),
    field("map", Supplier { mapOf("key" to "value") }),
    compositeField("struct", arrayOf(field("name", Supplier { "2" })))
)

    Schema.of(
    field("string", { -> "string" }),
    field("array", { -> [1, 2, 3] as int[] }),
    field("map", { -> [key: "value"] }),
    compositeField("struct", [field("name", { -> "2" })] as Field[])
)

    will lead to:

    INSERT INTO `MyTable` (`string`, `array`, `map`, `struct`) 
VALUES ('string', ARRAY(1, 2, 3), MAP('key', 'value'), NAMED_STRUCT('name', '2'));

    YAML transformation¶

    YAML transformation is very similar to CSV.

    The following is an example on how to use it:

    final BaseFaker faker = new BaseFaker();

YamlTransformer<Object> transformer = new YamlTransformer<>();
Schema<Object, ?> schema = Schema.of(
    field("name", () -> faker.name().firstName()),
    field("lastname", () -> faker.name().lastName()),
    field("phones", () -> Schema.of(
        field("worknumbers", () -> ((Stream<?>) faker.<String>stream().suppliers(() -> faker.phoneNumber().phoneNumber()).maxLen(2).build().get())
            .toList()),
        field("cellphones", () -> ((Stream<?>) faker.<String>stream().suppliers(() -> faker.phoneNumber().cellPhone()).maxLen(3).build().get())
            .toList())
    )),
    field("address", () -> Schema.of(
        field("city", () -> faker.address().city()),
        field("country", () -> faker.address().country()),
        field("streetAddress", () -> faker.address().streetAddress())
    ))
);

System.out.println(transformer.generate(schema, 1));

    val faker = BaseFaker()

val transformer = YamlTransformer<Any>()
val schema: Schema<Any, Any> = Schema.of(
    field("name", Supplier { faker.name().firstName() }),
    field("lastname", Supplier { faker.name().lastName() }),
    field("phones", Supplier { Schema.of<Any, Any>(
        field("worknumbers", Supplier { List(2) { faker.phoneNumber().phoneNumber() } }),
        field("cellphones", Supplier { List(3) { faker.phoneNumber().cellPhone() } })
    ) }),
    field("address", Supplier { Schema.of<Any, Any>(
        field("city", Supplier { faker.address().city() }),
        field("country", Supplier { faker.address().country() }),
        field("streetAddress", Supplier { faker.address().streetAddress() })
    ) })
)

println(transformer.generate(schema, 1))

    def faker = new BaseFaker()

def transformer = new YamlTransformer()
def schema = Schema.of(
    field("name", { -> faker.name().firstName() }),
    field("lastname", { -> faker.name().lastName() }),
    field("phones", { -> Schema.of(
        field("worknumbers", { -> (1..2).collect { faker.phoneNumber().phoneNumber() } }),
        field("cellphones", { -> (1..3).collect { faker.phoneNumber().cellPhone() } })
    ) }),
    field("address", { -> Schema.of(
        field("city", { -> faker.address().city() }),
        field("country", { -> faker.address().country() }),
        field("streetAddress", { -> faker.address().streetAddress() })
    ) })
)

println transformer.generate(schema, 1)

    will generate YAML with nested fields:

    name: Mason
lastname: Bechtelar
phones:
  worknumbers:
    - (520) 205-2587 x2139
    - (248) 225-6912 x4880
  cellphones:
    - 714-269-8609
    - 1-512-606-8850
    - 1-386-909-7996
address:
  city: Port Wan
  country: Trinidad and Tobago
  streetAddress: 6510 Duncan Landing

    Java object transformation¶

    Java Object transformer could be built with help of JavaObjectTransformer.

    When building JavaObjectTransformer you should provide a class to be used as a template for generated objects.

    import java.time.LocalDate;

public static class Person {
   private String firstName;
   private String lastName;
   private LocalDate birthDate;
   private int id;
}

    import java.time.LocalDate

data class Person(
    var firstName: String,
    var lastName: String,
    var birthDate: LocalDate,
    var id: Int
)

    class Person {
    String firstName
    String lastName
    LocalDate birthDate
    int id
}

    Then you should provide a schema for the class.

    JavaObjectTransformer jTransformer = new JavaObjectTransformer();
Schema<Object, ?> schema = Schema.of(
    field("firstName", () -> faker.name().firstName()),
    field("lastName", () -> faker.name().lastName()),
    field("birthDate", () -> faker.timeAndDate().birthday()),
    field("id", () -> faker.number().positive()));

System.out.println(jTransformer.apply(Person.class, schema));

    val jTransformer = JavaObjectTransformer()
val schema: Schema<Any, Any> = Schema.of(
    field("firstName", Supplier { faker.name().firstName() }),
    field("lastName", Supplier { faker.name().lastName() }),
    field("birthDate", Supplier { faker.timeAndDate().birthday() }),
    field("id", Supplier { faker.number().positive() }))

println(jTransformer.apply(Person::class.java, schema))

    def jTransformer = new JavaObjectTransformer()
def schema = Schema.of(
    field("firstName", { -> faker.name().firstName() }),
    field("lastName", { -> faker.name().lastName() }),
    field("birthDate", { -> faker.timeAndDate().birthday() }),
    field("id", { -> faker.number().positive() }))

println jTransformer.apply(Person, schema)

    will generate object with fields populated with random values based on specified suppliers.

    Java records¶

    Use a public record and provide a field for each component in the canonical constructor's order. To transform existing records in Datafaker 3.0, pass them to generate(inputs, schema). Each field function receives the input record, and the transformer returns a new record for each input in the same order.

    public record Customer(String name, int score) {}

Schema<Object, ?> schema = Schema.of(
    field("name", input -> ((Customer) input).name()),
    field("score", input -> ((Customer) input).score() + 1)
);

var transformer = new JavaObjectTransformer();
var updated = transformer.generate(List.of(new Customer("Alice", 10)), schema);
// [Customer[name=Alice, score=11]]

    @JvmRecord
data class Customer(val name: String, val score: Int)

val schema: Schema<Any, Any> = Schema.of(
    field("name", Function { input: Any -> (input as Customer).name }),
    field("score", Function { input: Any -> (input as Customer).score + 1 })
)

val transformer = JavaObjectTransformer()
val updated = transformer.generate(listOf<Any>(Customer("Alice", 10)), schema)
// [Customer[name=Alice, score=11]]

    record Customer(String name, int score) {}

def schema = Schema.of(
    field("name", { Object input -> (input as Customer).name() } as Function),
    field("score", { Object input -> (input as Customer).score() + 1 } as Function)
)

def transformer = new JavaObjectTransformer()
def updated = transformer.generate([new Customer("Alice", 10)], schema)
// [Customer[name=Alice, score=11]]

    Populating Java object with predefined schema¶

    You can use predefined schema to populate Java Object or default schema for the class. Schema should be declared as a static method with return type Schema<Object, ?>.

      public static Schema<Object, ?> defaultSchema() {
    var faker = new Faker(Locale.forLanguageTag("fr-en"), new RandomService(new Random(1)));
    return Schema.of(field("name", () -> faker.name().fullName()));
  }

    fun defaultSchema(): Schema<Any, Any> {
    val faker = Faker(Locale.forLanguageTag("fr-en"), RandomService(Random(1)))
    return Schema.of(field("name", Supplier { faker.name().fullName() }))
}

    static Schema<Object, ?> defaultSchema() {
    def faker = new Faker(Locale.forLanguageTag("fr-en"), new RandomService(new Random(1)))
    Schema.of(field("name", { -> faker.name().fullName() }))
}

    Then you should provide a class to be used as a template for generated objects. Class should be annotated with @FakeForSchema annotation with path to the schema method as a value.

    Note: If default schema and class template are in the same class, you can omit full path to the method and use only method name.

    @FakeForSchema("net.datafaker.annotations.FakeAnnotationTest#defaultSchema")
public class Person {
    private String name;

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}

    @FakeForSchema("net.datafaker.annotations.FakeAnnotationTest#defaultSchema")
data class Person(
    var name: String
)

    @FakeForSchema("net.datafaker.annotations.FakeAnnotationTest#defaultSchema")
class Person {
    String name
}

    Then you can use net.datafaker.providers.base.BaseFaker.populate(java.lang.Class<T>) to populate object with default predefined schema.

    BaseFaker faker = new BaseFaker();
Person person = BaseFaker.populate(Person.class);

    val faker = BaseFaker()
val person = BaseFaker.populate(Person::class.java)

    def person = BaseFaker.populate(Person)

    Use faker.populate(Person.class, schema) to supply a custom schema.

    BaseFaker faker = new BaseFaker();
Person person = BaseFaker.populate(Person.class, Schema.of(field("name", () -> faker.superhero().name())));

    val faker = BaseFaker()
val person = BaseFaker.populate(Person::class.java, Schema.of(field("name", Supplier { faker.superhero().name() })))

    def faker = new BaseFaker()
def person = BaseFaker.populate(Person, Schema.of(field("name", { -> faker.superhero().name() })))

    TOML transformation¶

    TOML transformation is similar to YAML and CSV.

    The following is an example on how to use it:

    final BaseFaker faker = new BaseFaker();

TomlTransformer<Object> transformer = new TomlTransformer<>();
Schema<Object, ?> schema = Schema.of(
    field("name", () -> faker.name().firstName()),
    field("lastname", () -> faker.name().lastName()),
    field("phones", () -> Schema.of(
        field("worknumbers", () -> ((Stream<?>) faker.<String>stream().suppliers(() -> faker.phoneNumber().phoneNumber()).maxLen(2).build().get())
            .toList()),
        field("cellphones", () -> ((Stream<?>) faker.<String>stream().suppliers(() -> faker.phoneNumber().cellPhone()).maxLen(3).build().get())
            .toList())
    )),
    field("address", () -> Schema.of(
        field("city", () -> faker.address().city()),
        field("country", () -> faker.address().country()),
        field("streetAddress", () -> faker.address().streetAddress())
    ))
);

System.out.println(transformer.generate(schema, 1));

    val faker = BaseFaker()

val transformer = TomlTransformer<Any>()
val schema: Schema<Any, Any> = Schema.of(
    field("name", Supplier { faker.name().firstName() }),
    field("lastname", Supplier { faker.name().lastName() }),
    field("phones", Supplier { Schema.of<Any, Any>(
        field("worknumbers", Supplier { List(2) { faker.phoneNumber().phoneNumber() } }),
        field("cellphones", Supplier { List(3) { faker.phoneNumber().cellPhone() } })
    ) }),
    field("address", Supplier { Schema.of<Any, Any>(
        field("city", Supplier { faker.address().city() }),
        field("country", Supplier { faker.address().country() }),
        field("streetAddress", Supplier { faker.address().streetAddress() })
    ) })
)

println(transformer.generate(schema, 1))

    def faker = new BaseFaker()

def transformer = new TomlTransformer()
def schema = Schema.of(
    field("name", { -> faker.name().firstName() }),
    field("lastname", { -> faker.name().lastName() }),
    field("phones", { -> Schema.of(
        field("worknumbers", { -> (1..2).collect { faker.phoneNumber().phoneNumber() } }),
        field("cellphones", { -> (1..3).collect { faker.phoneNumber().cellPhone() } })
    ) }),
    field("address", { -> Schema.of(
        field("city", { -> faker.address().city() }),
        field("country", { -> faker.address().country() }),
        field("streetAddress", { -> faker.address().streetAddress() })
    ) })
)

println transformer.generate(schema, 1)

    will generate TOML with nested fields:

    name = "Elaine"
lastname = "King"
[phones]
worknumbers = [ "(806) 207-5920", "(505) 640-6195" ]
cellphones = [ "(214) 287-6337", "(872) 940-4806", "(813) 294-1719" ]
[address]
city = "Lake Caitlin"
country = "Mongolia"
streetAddress = "5111 D'Amore Fall"

    TOML nulls and containers¶

    Null field values and null values in maps are omitted. Null elements in arrays, collections and streams are also omitted, while the remaining elements keep their relative order. A container containing only null elements is written as an empty array. Null keys are rejected. For duplicate schema field names, the first non-null value is used; suppliers after that value are not called.

    Nested schemas and composite fields become tables. Containers containing only non-null schemas become arrays of tables; mixing schemas with ordinary values in one container is rejected. Maps become inline tables, converting non-null keys using String.valueOf and quoting and escaping them as needed. Null keys and keys that collide after conversion are rejected. Other Iterable values, such as Path, are written as strings via toString() for compatibility. Streams returned by fields are consumed once and closed after serialization, including when an exception occurs. Each field stream is limited to 100,000 source elements, including nulls; exceeding the limit throws an exception rather than truncating it. Collections and arrays are not subject to this stream limit. Nested fields using functions receive the same input object as the enclosing schema.

    Cyclic structures and nesting deeper than 128 schema/container levels are rejected with an exception. Integers outside the signed 64-bit range are also rejected; BigDecimal values written with a decimal point or exponent remain TOML floats.

    Multiple TOML records¶

    A single record is written at the document root, as in the example above. Generating two or more records uses a records array of tables so that root keys and nested table headers are not redefined in the same document:

    [[records]]
name = "Alice"
[records.address]
city = "Paris"
[[records]]
name = "Bob"
[records.address]
city = "London"

    This applies to both generate(schema, limit) and generate(iterable, schema), and to the joined output of generateStream(schema, limit). Each non-null schema occurrence is preserved, including empty records and empty array-of-tables elements.
